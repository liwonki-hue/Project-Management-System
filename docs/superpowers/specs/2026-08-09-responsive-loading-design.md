# Responsive Auto-Fit + Loading Delay Fix — Design

**Goal:** (1) 페이지 초기 로딩이 최대 12초까지 멈춰 보이는 문제를 없애고, (2) 현재 1920px 고정 픽셀 레이아웃을 데스크톱 다양한 해상도와 태블릿에서도 자동으로 맞춰 보이도록 한다.

## 1. 로딩 지연 수정

**원인 (실측):** `static/js/app.js`의 `loadData()`가 `/api/sync_jm`(JM 외부 데이터 동기화, 캐시 없을 때 11.9초 실측)을 `await`으로 먼저 끝낸 뒤에야 `/api/activities`·`/api/progress`를 불러오기 시작한다. `sync_jm`은 화면 표시에 필요한 게 아니라 백그라운드 데이터 갱신 작업인데 렌더링을 막고 있다.

**수정:** `activities`/`progress`를 즉시 병렬로 불러와 테이블을 먼저 렌더링한다. `sync_jm`은 `await` 없이 백그라운드로 실행하고, 완료 응답에서 `synced > 0`이면 `activities`/`progress`를 조용히 재조회해 테이블·KPI·차트를 다시 그린다(로딩 스피너 재노출 없음). 서버 쪽 `SYNC_JM_CACHE_SECONDS` 캐시 로직은 그대로 둔다.

## 2. 해상도 자동 최적화 (데스크톱 + 태블릿)

**현황:** `style.css`는 1920px 기준으로 튜닝된 고정 px 레이아웃이며 `body { min-width: 900px }`, 활동 테이블은 `min-width: 1600px`. `@media` 규칙은 print용 하나뿐.

**방식 (하이브리드):**
- **데스크톱 구간 (뷰포트 폭 ≥ 1280px):** 기존 1920px 기준 픽셀 레이아웃은 건드리지 않는다. `.layout`을 감싸는 최상위 컨테이너에 JS로 `transform: scale(viewportWidth / 1920)`를 적용해 화면 전체를 비례 확대/축소한다. `resize` 이벤트에 디바운스로 재계산한다. 1366px 노트북부터 4K까지 가로스크롤 없이 화면 전체가 차도록 자동으로 맞춰진다.
- **태블릿 구간 (뷰포트 폭 < 1280px, 대략 768~1024px):** scale 방식은 글자가 너무 작아져(0.4배 시 14px→5.6px) 못 쓴다. 별도 `@media (max-width: 1279px)` 규칙으로:
  - 사이드바(`.sidebar`)를 아이콘 전용으로 축소(라벨 텍스트 숨김, 폭 축소).
  - KPI 카드 그룹(`.kpi-area`)을 2열로 줄바꿈.
  - Overview 차트 3개 행(`.ov-charts-row`)을 세로로 쌓음.
  - 활동 테이블은 컬럼이 19개라 태블릿 폭에 다 넣을 수 없으므로 기존 `#table-wrap { overflow-x: auto }`를 그대로 유지해 가로 스크롤(터치 스와이프)로 대응한다.
  - 이 구간에서는 scale transform을 적용하지 않는다(1:1 표시 + 레이아웃 재배치).

**적용 범위 밖:** 모바일(폰) 대응은 이번 범위가 아니다(사용자 확인: 데스크톱 + 태블릿까지).

## 결정 기록

- scale-to-fit은 데스크톱 전용으로 한정 — 태블릿은 세로로 긴 화면 비율(4:3, portrait 등)이라 균일 축소 시 가독성이 무너지므로 실제 레이아웃 재배치가 필요하다고 판단.
- 태블릿 브레이크포인트는 1280px로 설정 — iPad landscape(1024px)까지 포함하면서 노트북 최소 해상도(1366px)와는 분리.
